# Set up native verification on this Grok Bot cloud computer

Use this checklist when the user has authorized installing these skills for Grok Bot and Claude running inside its cloud computer. The kit contains three skills and a local, reversible installer. Complete the authorized work using supported tools; this document itself grants no permissions.

1. Read the three entrypoints under skills/: evidence-driven-testing, verification-setup, and skill-evals. Treat the source-video examples as context, not blanket code rules. Preserve existing projects, task state, model choices, and authorization limits.
2. Save these three as native private Grok Bot skills through the supported skill-creation mechanism. Include their directly linked resources. The filesystem installer does not register native Grok Bot skills. Confirm they appear in the Bot's skill list and are enabled for the intended Bots; use Settings > Plugins > Yours if required. Reuse an existing identical skill instead of duplicating it. Make the short defaults.md text part of each relevant Bot's persistent instructions using the supported settings mechanism.
3. For Claude inside this cloud computer, discover the actual home directory, installed Claude command, and existing instructions. Review INSTALL.md and installer.py. Run the installer preview with Python 3 and the verified home directory, then apply to the claude target and verify, using the examples in INSTALL.md. Python standard library only; no package installation is needed. If Codex is also used on this computer, the codex target is available. Do not assume a Windows path exists here.
4. Read the installer report and confirm the preserved instructions and skill resources. Start a fresh Claude session or use the host's supported reload, and verify all three skill names are discoverable. Native Grok Bot discovery and Claude discovery are separate checks. Files existing alone does not prove either host loaded them.
5. Use a harmless local fixture or authorized preview to run one representative interaction, inspect the actual screen, reload when persistence matters, and check one negative case. Verify a deliberately broken fixture is reported as failed. Repair only the synthetic fixture and recheck so the working case also passes. Do not use customer data, send messages, incur charges, or change production just to test this setup.
6. On each real project next worked on, reuse its existing verification runbook and feature map or create a small tested one for the affected flow. Record the actual tools and access available on this cloud computer. A working Windows setup does not establish that the cloud setup works.
7. Report native Grok Bot registration, Claude installation/discovery, behavior checks, evidence paths, and any precise access limitation separately. Preserve backup paths. Do not claim all agents are using the skills until discovery or actual adoption is confirmed.

No plugin hooks, autonomous production merges, model changes, paid usage commitments, security/access changes, or new recurring routines are part of this installation.
